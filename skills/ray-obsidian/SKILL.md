# ray-obsidian：内容知识库的骨架

把内容生产要用的目录、模板和流程说明装进用户自己的本地目录。新库从零建，已有的库只补缺的部分。终点是结构检查为 `ready` 的知识库，以及用户知道东西该往哪放。

`$SK` 指本 skill 目录。

## 先分清任务

| 用户要的 | 怎么走 |
|---|---|
| 只检查结构 | 做第 1、2 步就交付。不借机初始化 |
| 新建一个库 | 第 1–5 步 |
| 把已有的 Obsidian 库接进来 | 第 1–5 步，第 2 步多读 [migration.md](references/migration.md)，只做增量，不整理旧笔记 |
| 升级 `ray-content-v1` 的旧库 | 同上。检查会把它报成 `incomplete`，初始化只升级 manifest、补缺失结构，旧目录和文件都留着 |
| 批量移动、改名、合并、清附件、开 Git、迁云盘、改 Obsidian 设置 | 不自动做。先给逐项计划，用户确认后再动 |

## 原则

1. **根目录由用户定，不猜。** 不默认叫 `rays-brain`，不假设在 iCloud、主目录或当前项目里。写错地方等于在别人的项目里撒了一堆目录。
2. **用户已有的文件优先。** 不覆盖同名文件，不自动移动、改名、删除，不批量改 frontmatter。同名模板以用户的版本为准。
3. **不碰 `.obsidian/`。** 不强制插件、同步服务、Git 或某个云盘。Obsidian 只是编辑器，普通 Markdown 工具也能用这套结构。
4. **只建最小骨架。** 采集自动化、网页剪藏、X 数据和发布连接器，用户要时另外配。
5. **原始资料、长期知识、创作过程、发布成品分开放。** 目录表达职责，链接表达关系。
6. **建完要检查。** 目录在，不等于知识库能用。

## 流程

### 1. 确定根目录

按顺序找：

1. 用户明确给的目录。
2. 当前目录或父目录里的 `.ray-obsidian.json`。
3. 当前目录或父目录里同时有 `10-创作/`、`20-知识/`、`30-资料/`、`50-系统/` 的兼容结构。
4. 都没有，只问一个问题：知识库要建在哪个本地目录？

定下来后先报告绝对路径。目录名里带 `brain`、`notes` 或 `vault` 不是依据，不要因此直接写入。

### 2. 检查

```bash
python3 $SK/scripts/vault_setup.py check --vault <知识库目录>
```

| 结果 | 下一步 |
|---|---|
| `ready` | 直接交付 |
| `incomplete` 或 `missing` | 读 [vault-schema.md](references/vault-schema.md)，向用户简要说明会新增哪些目录和模板，再往下走 |
| manifest 无法解析，或声明了不认识的结构版本 | 停下报告，不覆盖修复 |

### 3. 预演，再初始化

```bash
python3 $SK/scripts/vault_setup.py init --vault <知识库目录> --name <知识库名称> --dry-run
python3 $SK/scripts/vault_setup.py init --vault <知识库目录> --name <知识库名称>
```

先看预演的清单，确认目标没跑偏再正式执行。脚本只做四件事：建缺失的目录；从 `assets/vault-template/` 复制缺失的说明、流程和模板；新建 `.ray-obsidian.json`，让别的 skill 能认出结构版本；把所有已存在的文件原样留下，并在结果里列为 `preserved`。

### 4. 复核

重新跑一次 `check`，并真的打开这几个文件看一眼：

- `HOME.md`
- `00-入口/10-工作台/知识工作台.md`
- `00-入口/10-工作台/创作工作台.md`
- `50-系统/30-模板/内容成稿包.md`
- `50-系统/30-模板/快速口播母稿.md`
- `50-系统/20-流程/个人知识库工作流.md`

完成的标准：状态是 `ready`；脚本报告里没有覆盖、移动或删除任何已有文件；manifest、目录和核心模板齐全。

### 5. 交接

把知识库的绝对路径交给用户，说明怎么在 Obsidian 里打开这个目录，以及三个最小入口：

- **进来的东西**：新资料放 `30-资料/`，自己的即时想法放 `10-创作/10-灵感/inbox.md`。
- **要写的东西**：值得表达的角度先进 `10-创作/10-灵感/20-候选选题/`；确定了这次的角度，才在 `10-创作/20-写作任务/` 建成稿包。
- **写出来的东西**：图文母稿进 `10-创作/30-文章草稿/`；直接以口播起稿的，用 `50-系统/30-模板/快速口播母稿.md`，放进 `10-创作/25-口播草稿/`。确认发布后才进 `40-发布/`，在 `40-发布/00-内容反馈/` 复盘。

用户接着要写文章时，把知识库根目录、材料路径和目标平台交给 `ray-writer`。不把整套知识库复制进 skill 目录，也不把用户的笔记拿来当 skill 的样本。
