# Codex + Obsidian 内容生产最小包

这组模板只用于第一次跑通“素材进入 → 判断 → 选题 → 写作 → 发布 → 回流”。它和本知识库正式流程里的成稿包、口播母稿并行存在，不会因为放在模板目录里而出现在工作台。

## 六个对象

1. `10-原始素材.md`：保存可反复核对的原文。
2. `20-审核卡.md`：让 AI 提炼，让人决定知识价值和写作价值。
3. `30-候选角度.md`：只保存一个可能写的角度，不提前开工。
4. `40-写作任务.md`：确认这一次只写什么，以及事实边界。
5. `50-母稿.md`：所有平台版本共同使用的唯一正文来源。
6. `60-发布反馈.md`：确认公开发布后，记录知识、剩余角度和数据回流。

这六个文件属于一次内容运行。另在同一 vault 建立共享的 `knowledge/` 目录，保存跨内容复用的结论、适用边界、反例和原始来源。知识不归属于某一篇文章。

## 第一次怎么跑

1. 把 `10` 到 `60` 的六个文件复制到新的 `content-run/`，填满 `10-原始素材.md`。
2. 让 Codex 读取原始素材并填写 `20-审核卡.md`，但不要替你勾选去向。
3. 你分别判断知识价值与写作价值。确认有知识价值时，由人批准新建或更新 `knowledge/` 中的知识笔记。
4. 只有确认要写，才填写 `30-候选角度.md`。选定一个角度后，先搜索相关旧知识、反例和来源，再填写 `40-写作任务.md`。
5. 核实事实边界以后，才让 Codex 协作完成 `50-母稿.md`。
6. 平台版本只能改标题、段落和排版，不能增加母稿里没有的事实。
7. 人工确认公开发布后，再填写 `60-发布反馈.md`。

## 三段可复制指令

### A｜审核与分流

```text
只读取 10-原始素材.md，不要修改原文，也不要开始写文章。
填写 20-审核卡.md：摘要、事实候选与对应证据位置、不确定或待核对处、
与已有知识的关系，以及 3 个彼此不同的候选角度。
完成后停止，等待我分别决定：
1. 是否进入长期知识；
2. 是否建立写作候选。
如果确认进入知识，先说明应新建还是更新哪条知识，等待我批准。
```

### B｜建立单角度任务

```text
只读取已经确认的审核卡和候选角度。
先搜索 knowledge/，列出相关判断、适用边界、反例和来源，
等待我确认本篇实际调用哪些旧知识。
围绕 30-候选角度.md 中唯一选定的角度填写 40-写作任务.md，
不要把其他角度混进当前任务。
分开记录：已核实事实、来源观点、作者推论、待核对内容和禁止补写项。
人工确认前，不要生成完整正文。
```

### C｜生成唯一母稿

```text
只根据 10-原始素材.md、20-审核卡.md 和已经确认的 40-写作任务.md
协作完成 50-母稿.md。
关键事实保留来源；待核对内容不得写成事实；
不得新增我没有提供的经历、数字、情绪或结果。
参考来源保留在母稿末尾，平台版本不新增事实。
```

## 第一次验收

让 Codex 只读取共享的 `knowledge/` 和这次的 `content-run/` 并回答：

```text
1. 原始资料发表于什么时候，完整原文在哪里？
2. 这次只写哪一个角度？
3. 这份素材新建或更新了哪条长期知识？当前任务调用了哪些旧知识和反例？
4. 已核实事实、来源观点、作者推论和待核对项分别是什么？
5. 母稿是否已经满足平台适配条件？
6. 是否已经公开发布？没有就明确回答“未发布”。
7. 下一篇还剩哪些未使用角度？

每项注明来源文件。找不到就说找不到，禁止补写。
```

如果离开聊天记录，它仍能从共享知识和六个运行文件中准确回答，最小系统才算跑通。

## 发布检查

- [ ] 原文、作者、链接和原始时间已经保存
- [ ] 知识价值与写作价值分别由人判断
- [ ] 新知识已经写回，当前任务调用的旧知识已经列明
- [ ] 当前任务只有一个角度
- [ ] 事实、来源观点、作者推论和待核对项已经分开
- [ ] 母稿保留参考来源，平台版本没有新增事实
- [ ] 图片承担证明或解释作用
- [ ] 两个平台分别检查标题、正文、图片和封面
- [ ] 公开发布由人确认，链接和时间已经回写
- [ ] 新知识、剩余角度和反馈已经安排去向
