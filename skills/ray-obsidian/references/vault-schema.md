# Ray 本地知识库结构

## 设计目标

这套结构服务于两个循环：资料逐步变成可复用知识；知识与真实材料被装配成内容并在发布后回流。它不是百科全书，也不要求一次整理完历史笔记。

## 目录职责

| 目录 | 职责 |
|---|---|
| `HOME.md` 与 `00-入口/10-工作台/` | 总入口、知识工作台、创作工作台与人工检查点 |
| `00-入口/20-日报/` | 自动化生成的健康日报、周报和知识地图整理（随工作台套件出现，初始化不建） |
| `10-创作/10-灵感/10-待评估/` | 尚未决定是否推进的选题与审核卡 |
| `10-创作/10-灵感/20-候选选题/` | 已通过分流、尚未确定本次写作角度的候选 |
| `10-创作/10-灵感/90-选题储备/` | 有价值但近期不推进的选题 |
| `10-创作/20-写作任务/` | 已确定一个角度的成稿包 |
| `10-创作/30-文章草稿/` | 图文母稿，以及从长文改出的口播稿 |
| `10-创作/25-口播草稿/` | 直接以口播起稿、没有图文母稿的内容 |
| `20-知识/` | 可长期复用的概念、观点、案例、方法与地图 |
| `30-资料/` | 外部原文与自己的输出，不与长期知识混放：`00-待抓取`、`10-自主调研`、`20-参考资料`、`30-X书签`、`40-网页剪藏`、`50-读书划线`、`60-我的推文`（写作和短推风格的样本来源）；按需再加 `70-人物语料` 等 |
| `40-发布/` | 用户确认后的发布版本、公开信息与发布反馈：`00-内容反馈`、`10-X长文`、`20-X短帖`、`50-口播视频`；公众号的草稿与发布状态记在正式稿的 frontmatter 里，不单独建目录 |
| `50-系统/` | `10-文档` 设计说明、`20-流程` 流程、`30-模板` 模板；工作台套件还会加入 `40-自动化`、`50-视图`、`60-维护`，初始化不建 |
| `60-素材/` | 图片（`10-图片/10-封面/` 放封面任务包和平台成品）、录音转录；按需再加演示文稿、平台交付、调研媒体 |
| `70-思考/` | 尚不适合变成正式知识或内容的个人思考，以及 `当前关注.md` |
| `90-归档/` | 失效但仍需保留的内容；不作为删除区。可按迁移记录、审核记录、创作记录、系统报告分子目录 |

## 模板

`50-系统/30-模板/` 只放实际在用的模板：

- `内容成稿包.md`：一次写作任务的唯一成稿包。
- `快速口播母稿.md`：直接以口播起稿时的唯一母稿。
- `内容反馈.md`、`口播视频反馈.md`：图文与口播视频发布后的 24 小时 / 7 天反馈。
- `当前关注.md`：复制到 `70-思考/` 后填写，工作台和 Agent 用它判断什么重要。
- `内容生产最小包/`：第一次跑通「素材 → 判断 → 选题 → 写作 → 发布 → 回流」的六个对象和使用说明，不进入工作台。

知识笔记不设单独模板：按下面的 `kind` 写 frontmatter 即可。

## 知识分类

长期知识使用 frontmatter 的 `kind` 作为分类真源：

- `concept`：概念
- `entity`：人物、组织、公司、产品或模型；具体类型由 `entity_type` 区分
- `question`：值得持续回答的问题
- `viewpoint`：可辩论的判断
- `case`：案例
- `playbook`：方法与操作方案
- `map`：主题地图
- `guide`：导航与系统说明

目录只是浏览便利。不要因为移动文件而批量改写知识类型。

## 最小内容流

1. 原始输入进入 `30-资料/`，保持来源与链接。
2. 值得长期复用的部分提炼为 `20-知识/` 的独立笔记。
3. 值得表达的角度先进入候选选题；只有确认近期推进和本次角度后才建立成稿包。
4. 调研进入 `30-资料/10-自主调研/<主题>/`，图文母稿进入 `10-创作/30-文章草稿/`；直接起稿的口播母稿进入 `10-创作/25-口播草稿/`。
5. 用户确认公开发布后才进入 `40-发布/`，并建立发布反馈记录。
6. 发布形成的新观点、案例和方法回流为独立知识；已用和剩余角度回写候选，不把整篇文章复制到知识区。

## 两套注意力时间

- 资料时效根据来源发布时间判断，过期表示写作前需要重新核对，不自动删除来源。
- 候选注意力从进入候选池当天计算，默认 7 天；超期时先确保长期知识已沉淀，再关闭候选，不自动建立写作任务。
- 待审核资料默认每天只展示最值得判断的少量项目；自动化可以在严格条件下先保留高把握知识，但不得替人决定是否写作。

## 命名与版本

- 成稿包：`YYYY-MM-DD-主题.md`
- 调研目录：`YYYY-MM-DD-主题/`
- 草稿：`YYYY-MM-DD-标题.md`
- 文件名使用有意义的人类语言，不用随机编号代替主题。
- 同一主题只保留一份当前草稿；历史版本交给 Git、同步服务或归档目录处理。
