# 解说稿规则（script.json）

## 结构

```json
{
  "title": "片名", "source": "素材路径或 URL", "header": "一篇读懂 · 主题",
  "voice": "Charon 或已注册的复刻音色名（如 ray）", "speed": 1.0,
  "gaps": { "lead": 0.6, "line": 0.32, "scene": 0.8, "tail": 1.6 },
  "scenes": [ { "id": "hook", "lines": ["第一句", "第二句"] } ],
  "to_confirm": ["编补或存疑的说法，交付时列给 Ray"]
}
```

- `id` 只用英文小写。kit 场景和 `scenes.js` 里的 `S.<id>` 一一对应；语法场景另写 `grammar` 和 `cues`，见 [grammars.md](grammars.md)。完整范例：`assets/template/script.example.json`。
- 每句 12–50 字。Charon 实测语速约 4 字/秒，2.5 分钟大约需要 550–650 字、25 句左右。
- 场景数 7–10 个，每场 1–4 句。一个场景只讲一件事、只配一个主画面。

## 写法（来自 Ray 的写作规则）

1. **表达先行**：用 Ray 本人的口吻把判断说满，不写“可能”“某种程度上”“值得注意的是”。
2. **正文不自保**：拿不准、编补、夸张的内容照样写进稿子，但必须同时记进 `to_confirm`，由 Ray 决定去留。
3. **贴合大陆观众**：例子和说法用国内观众熟悉的，人名和产品名第一次出现时顺手交代一句是谁、是什么。
4. **“不是……而是……”全稿最多 2–3 处**，只留真正承担反转功能的那几处，其余换成别的句式。
5. 口语化，句子能直接念出来；不写书面腔，不写括号注释（TTS 会把括号里的内容也念出来）。

## 开头（前 3 句，约 15 秒）

- 第一句就给出冲突或反常识的现象，不寒暄，不说“今天我们来聊聊”。
- 第三句前抛出问题，第四句前给出反直觉的答案或态度，用答案把人留下来。
- 范例：排行榜每周换第一 → 换模型只要改一行代码 → 那 AI 公司靠什么赢？ → “模型强不强，根本不是重点”。

## 主体

- 按“结论 → 拆解 → 证据或故事”推进，每个场景结尾都要给出往下看的理由。
- 文章里的框架（几根杠杆、三条路）最适合画成图，优先保留。
- 引语只保留最有力的一句，交代说话人是谁。

## 结尾的“收获”

- 落到一个观众带得走的东西：三个问题、一个判断标准、一个动作。
- 最后一句短、有力，最好能指回观众自己。

## 画面友好

- 每句话里要有一个能被画出来的名词或动作（排行榜、聊天框、漏斗、箭头反转）。
- 需要画面卡点的关键词要原样写在句子里，`at(sc, i, '关键词')` 才能找到它的时刻。
