# 风格库

一种风格就是一整套可以直接拿来用的成片做法，包括版式、字体、色板、动效、声音、工程模板，以及踩过的坑。每种风格至少要有一条 Ray 认可过的成片，新片照着做就能达到那个水平。

它和 [style-refs.md](../style-refs.md) 不一样：

| | 参考卡（style-refs） | 风格库（styles） |
|---|---|---|
| 是什么 | 抽帧看别人怎么做，只借版式、节奏和信息组织 | 已经在 Ray 的片子上做出来、Ray 认可的完整做法 |
| 颜色 | 一律换成 IP 色板（[ip-style.md](../ip-style.md)） | 风格自己定。例如口播打底的片子从房间取色，在风格文档里写明 |
| 带模板 | 不带 | 带：`assets/styles/<id>/` 是能直接构建的 HyperFrames 工程 |

## 怎么用

1. Ray 点名某种风格时用那种。没点名时：整段真人口播要剪成课程片，用 `ali`；科普解说片（横屏），用 `xiaolin`；整段真人口播要做成竖屏短视频、配卡片和动效，用 `fenping`。读对应的风格文档，按里面的「做一条新片」做。
2. 模板是上一条成片的完整工程，`build.py` 会顺带写出 `scenes.json`，给审片页和成片检查用。复制过去以后，场景换成这一期的内容，CSS、动效函数、`build.py` 的结构保持不变。
3. 做完一条以后，Ray 提的修改如果是这种风格通用的（比如字号、位置、颜色），就改回风格文档和模板；只跟这一期有关的不改。

## 加一种新风格

一种做法在 Ray 的成片上认可过以后才进库。每种风格要有这几样：

- 一份风格文档 `references/styles/<id>.md`，写清来源、适合什么、视觉规范（带具体数值）、动效、声音、做一条新片的步骤、踩过的坑、Ray 的修改记录。
- 一份模板 `assets/styles/<id>/`，就是那条成片的工程，去掉素材文件。模板的 `build.py` 必须同时写出 `scenes.json`：每个镜头一行，包括 id、起止秒、`label`（画板、口播或素材名）、`visual`，以及那段时间说的话。审片页（`review.py`）和成片检查（`qa_video.py`）都按它分段。
- 在上面「现有风格」表里加一行。
