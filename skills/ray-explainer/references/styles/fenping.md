# 风格 `fenping`：竖屏真人口播 + 分屏卡片

学的是 Instagram reel https://www.instagram.com/reel/DPoXbzZjb8J/。做法是真人口播打底，按说的内容在三种版式之间切换，配逐词组字幕。

第一条成片是《为什么企业上 AI，前半年几乎看不到效果？》v2，2026-10-26 完成，时长 2 分 8 秒。工程在 Ray 本机 `~/Movies/ray-explainer/2026-10-26-ai-percolation-koubo/hf`。模板 `assets/styles/fenping/` 就是这个工程，去掉了真人素材、人声、配乐和图片。四个音效留在里面，都是 ffmpeg 合成的。

## 适合什么

- Ray 对着镜头录了一整段观点口播或科普口播。原片是横屏、固定机位、1–3 分钟。要做成抖音、视频号、小红书用的竖屏 1080×1920。
- 内容里有数字、年代、人名、原理，适合用卡片和示意动画讲清楚。
- 不适合的情况：
  - 横屏课程片走 `ali`。
  - 纯配音的解说片走 `xiaolin` 或 SKILL.md 主链路。
  - 只加字幕不加卡片，走 `embedded-captions`。

## 一眼看上去

三种版式，镜头表里每段选一种：

| 版式 | 画面 | 用在哪 | 第一条成片的比例 |
|---|---|---|---|
| **A** 全屏真人 | `face_full.mp4` 铺满 1080×1920，情绪句推近到 1.09 | 抛问题、转折（“为什么？”）、收尾 | 约 16% |
| **B** 分屏 | 上半屏 1080×960 是卡片或示意，下半屏 y 960 起放 `face_half.mp4`（头肩） | 讲数字、讲一个对比，同时要看到人 | 约 37% |
| **C** 全屏画面 | 整屏卡片、老照片、人物照、名词字卡 | 讲人物、讲名词、讲需要大面积的示意（网格贯通） | 约 47% |

- 版式之间一律硬切，不做转场动画。动的只有画面里的元素。
- 讲到一个人时用 C，放这个人的真实照片，配英文原名和论文、年份。讲一个名词时也用 C，整屏墨绿底加英文原词，例如 `percolation`。这两种都不用 B，因为分屏时字卡会挡住嘴（Ray 10-26）。
- 示意动画用一套贯穿全片的图形，第一条成片用的是渗流网格（`lib/perc.js`）。同一个图形反复出现，观众记得住。

## 视觉规范

**色板**：用 IP 色板（[ip-style.md](../ip-style.md)），每个镜头只有一处墨绿。

```
#f3f3f0 卡片底（暖白）   #111 正文、黑胶囊   #6e6e6e / #8c8c8c 次要字
#054c4c 墨绿：强调、名词字卡底   #9cc2bf 浅墨绿：字幕重点词、深底上的强调
#e4e4e0 浅灰胶囊   #c9c9c5 / #dddcd8 未激活的线和条
```

**字体**：思源黑体 woff，包括 Medium 500（`Hei`）、Bold 700（`HeiBold`）、Heavy 900（`HeiHeavy`）。`prep.py` 会从 skill 的 `assets/huashu/lib/fonts/` 把这几个文件复制到 `assets/fonts/`，不裁子集。每个文件 1.4 MB，渲染时不碍事。

**字号**：
- 大数字和年份用 900，字号 110–220。
- 卡片标题用 700，字号 44–60。
- 胶囊用 38。
- 次要字用 500，字号 34–38。

**字幕**（`build.py` 的 `CAPS` 生成 `compositions/captions.html`）：
- 每组 2–8 个字，按说话节奏断开，取 whisper 的逐字时间。
- 样式是黑胶囊：`rgba(17,17,17,.84)` 底，HeiBold 64，暖白字，圆角 18。
- 位置：B 段在接缝处（top 918），盖住上下两半的分界线。A、C 段偏下（top 1196）。`build.py` 按镜头表自动选位置。
- `*词*` 标浅墨绿重点，一个镜头最多一处。

**安全区**：
- C 段和 A 段的卡片内容放在 y 1150 以上，给下面的字幕让位。
- B 段的上半屏内容放在 y 160–860 之间。
- 不能压住下巴和嘴。真人的脸在 B 段下半屏的上三分之一，卡片不越过 y 960。

**画面里的字不和字幕重复**（Ray 10-26，最重要的一条）：字幕已经把话说了，画面就放字幕里没有的东西：
- 出处，例如 `MIT NANDA 2025`。
- 英文原词。
- 数字和年份。
- 图形：条、线、网格、箭头。
- 照片。

画面上一句完整的中文都不要写。实在要标注，只用 2–4 字的名词标签，而且这个词不能出现在同一时刻的字幕里。

## 动效

- 元素进场：淡入，上移 10–20px，0.25–0.4 秒，`power2.out` / `power3.out`。不用回弹。
- 数字用 count-up；条形用 `scaleX` 从左长出来；线条用 `strokeDashoffset` 画出来。
- 每个动作对准说到那个词的时间。场景内的时间从场景开始算，写在场景脚本的注释里（“场景从 40.2 秒开始”）。
- A 段推近：`#face-a-wrap` 在情绪词上 0.22 秒推到 `scale 1.09`，变焦中心在 `50% 32%`，下一段开始时 `set` 回 1。
- 网格：`makeGrid(svgId, 列, 行, 种子, x0, y0, 间距)`、`critical(G)` 求贯通点、`paint(G, p, opts)` 按打通比例上色。种子要固定。第一条成片用的是种子 96（12×16）和 64（12×7），贯通点约在 49.85%。改网格场景只改 `scenes_src/`，然后跑 `build_scenes.py` 注入到 `compositions/`。

## 声音

- 人声：`prep.py` 调 `gate_breaths.py`，把句间吸气压到 −45 dB，时间轴不变。所以镜头表、字幕都按原片时间写。
- 配乐：`gen_bgm.py` 用 ACE-Step 本地生成，`script.json` 里有上一条的 caption，节奏 84 bpm。前半段不加鼓，后半段打开。音量 0.32。
- 音效约 10 处，全片不超过 12 处：
  - `ding`：大数字出现时，音量 0.3–0.35。
  - `click`：一条线点亮、一台电机装上时，音量 0.35–0.5。
  - `whoosh`：切到名词字卡时，音量 0.4。
  - `swell`：全片高潮，网格整片贯通时，音量 0.55。
- 出片后统一响度：`loudnorm=I=-16:TP=-1.5:LRA=11`。第一次出片峰值到了 +1.5 dBFS，一定要做这一步。

## 做一条新片

1. **建工程**：
   ```
   mkdir -p <工程>/hf && cp -R $SK/assets/styles/fenping/. <工程>/hf/
   ```
   `$SK` 是 `~/.claude/skills/ray-explainer`。
2. **量脸**：从原片抽一帧，加网格，量鼻梁的 x 像素。
3. **准备素材**：
   ```
   python3 prep.py <原片.mov> --face-x <像素> [--end <秒>] [--mic-trim 0.074]
   ```
   - 产出 `face_full`、`face_half`、`voice.wav`、`end_still.jpg`、字体，以及 `../words.json`。
   - 先加 `--dry-run` 看一遍裁切参数。
   - `--end` 截掉结尾的 NG 和空白。
   - `--mic-trim` 控制话筒露多少。Ray 说话筒可以藏一点点，0.074 刚好。
4. **写镜头表和字幕表**：照 `words.json` 改 `build.py` 的 `SEG` 和 `CAPS`，`FOOTAGE_END` 填 prep 打印的时长。
   - 镜头表的段与段首尾相接，不能有空档。
   - 最后一段是 A，结尾多出 0.1 秒左右，由 `end_still` 垫帧。`index.html` 里 `#end-still` 的时间要跟着改。
5. **写场景**：
   - 每个 B、C 段写一个 `compositions/s-<id>.html`。旧场景能改就改，组件都能复用：大数字、条形、年代、照片卡、名词字卡、S 曲线、网格。
   - 示意图形有公共代码的，放进 `lib/`，写在 `scenes_src/` 里。
   - 删掉这一期用不到的旧场景。
   - 音效写在 `index.html` 的 `<audio>` 里，对准词的时间。
   - 图片放 `assets/img/`，授权写进 `publish.md`。
6. **构建、检查**：
   ```
   python3 build.py && python3 build_scenes.py
   npx --yes hyperframes@0.8.181 check --json
   npx --yes hyperframes@0.8.181 snapshot --describe false --at <每段一个时间点>
   ```
   `--describe false` 不能省，否则会把帧发给外部模型。看拼图，至少检查这几点：
   - 卡片有没有压到下巴和嘴。
   - 字幕和画面里的字有没有重复。
   - 标签有没有压到线。
   - C 段的内容有没有掉进字幕带。
7. **配乐**：`gen_bgm.py` 出 3 条，挑一条，转成 `assets/audio/bgm.m4a`。
8. **出片**：
   ```
   npx --yes hyperframes@0.8.181 render -q delivery -o raw.mp4
   ```
   然后用 loudnorm 统一响度，视频流直接复制，再跑 `phone_export.py` 出手机版。
9. **审片**：先跑 `qa_video.py --lufs -16`，再开 `review.py --tailnet`，读 `../scenes.json`，按 Ray 的批注改。通用的修改改回本文档和模板。
10. **封面**：一张 3:4，走 `ray-cover` 的视频封面（默认小Lin风A），用这一期的标题和 Ray 的真人照片。不出 9:16、16:9，除非 Ray 要。

## 踩过的坑

- 所有视频都要 30 fps、`-g 30` 编码（`prep.py` 已经这样做）。关键帧太稀的话，HyperFrames 逐帧 seek 会卡，或者花屏。
- `<video>` 只给自己定时，不放进带时间的元素里。A 段视频放在没有时间的 `#face-a-wrap` 里，推近也是动这个外层。
- 画面先于字幕结束会穿帮：最后一句字幕比素材长时，用 `end_still` 垫上。
- 分屏下半屏的卡片标签容易压到下巴。B 段上半屏内容不越过 y 860。
- 标签放在曲线或横线附近时，留出 24px 以上的间距（10-26 的 “≈40” 压到了横线上）。
- C 段里网格的底边要和字幕带隔开，第一条成片把间距从 64 改成了 52，网格才放得下。
- 场景里用了 `transform` 的元素，GSAP 就不能再动它的 x、y。位置写在外层，动画放在内层。
