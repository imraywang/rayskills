# 发布包与发布回流

## 发布包

用户认可成片后，在 `script.json` 里写两样东西：
- `cover_t`：封面取第几秒的那一帧。
- `publish`：`titles`（标题备选）、`description`（描述）、`tags`（标签）。写法遵循 Ray 的写作规则：直接、口语化。

然后：

```bash
python3 $SK/scripts/publish.py <project> --vault <知识库根目录>
```

- 生成 `cover.jpg`，这一帧不带字幕和进度条。
- 生成 `publish.md`，标题、描述、标签可以直接复制粘贴。
- 在 vault 的 `10-创作/25-口播草稿/<日期>-<标题>.md` 写一篇笔记。frontmatter 记录视频路径、时长、音色、画法、待确认条数；正文是分镜表、逐字稿和发布文案。视频本身不复制进 vault。
- **视频来自一篇已有的口播母稿**（ray-kb 快速口播等）时，在 `script.json` 写 `"draft": "<母稿在 vault 里的相对路径>"`。这样脚本不新建笔记，只给母稿加 `video_*` 字段和「发布文案」一节；重跑会替换，不会叠出两份，也避免和母稿同名撞文件。
- 成片不叫 `out.mp4` 时，在 `publish` 里写 `"video": "<文件名>"`。HyperFrames 项目（有 `hf/build.py`）的封面用 COVER 版单独渲一帧，见 [hyperframes.md](hyperframes.md)。
- 用户手动改过这篇笔记的话，脚本会拒绝覆盖；确认要替换时才加 `--force`。

交付时提醒两件事：
- 平台的「AI 生成内容」声明要勾选（用了复刻音色、数字人）。
- 用了 CC 授权图片的，要在简介里署名。

**封面**交给 `ray-cover` 的视频封面流程（Ray 真人照片加大标题，黑白灰加墨绿 IP）：
- 竖屏片默认只出 3:4（`xhs`，风格默认小Lin风A），拷成项目根目录的 `cover_3x4.png`。9:16 只在 Ray 明确要时才出。
- 横屏片出 `landscape`（16:9，1920×1080），另出一份 jpg 给 YouTube。
- `cover.jpg`（成片里的一帧）只作备用。

## 发布回流

视频发出去之后，平台链接和数据用知识库的 `platform_sync.py` 从后台核对，然后在正式稿上做回流。视频来自 `ray-kb` / `ray-kepu` 的母稿时，规则和那边一样。

**发布回流三问**：归档时当次做完，不留 `pending`。正式稿末尾的「回流」小节（模板里有）每行写链接，或者写「无」：

1. **机制与类比 → 长期知识**：这期有没有能迁移到别的题目上的机制、类比、反直觉结论？先用 `knowledge_search.py` 查库里有没有：有就补进旧笔记，没有再新建概念或观点笔记，正文链回本篇正式稿和调研。
2. **带日期的事实 → 对象档案时间线**：这期查实的关键数字和事件，按事实发生的日期，记进人物、公司、产品档案。
   ```bash
   python3 <vault>/50-系统/40-自动化/知识采集/entity_timeline.py --from facts.json --write
   ```
   先不加 `--write` 预览一遍。新对象在那一条里加 `"create": "公司"`。没有日期的事实不记。知识库里没有这个脚本时，在档案里手写一节 `## 时间线`，每行写 `- YYYY-MM-DD 事实（来源：链接）`。
3. **讲法与反馈 → 留在本篇**：哪个开头、类比、画面有效，在平台审核或数据上踩了什么坑。

三行都答完，`knowledge_backfill_status` 才写 `complete`；三行都是「无」时写 `not-needed`。下次同主题开工时，知识库预检会把这三样一起找出来。
