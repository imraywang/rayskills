# 数字人主持人

**角落主持人是 IP 默认，不用问。** `script.template.json` 自带 `"host": { "avatar": "ray", "big": [] }`，全片左下角换嘴型图层，不花钱。只有**大机位**（默认 MiniMax H3）要先 `--dry-run` 报价、Ray 同意才生成；`big` 留空就不生成。删掉 `host` 字段才是不带主持人。

## 效果

- **大机位**：主持人大半身站在画面下半部中间，带手势、歪头、表情，嘴在动。默认用 **MiniMax H3** 图生视频：「形象图 + 动作提示词 + 这句的字」生成，不按配音逐字对口型——大机位要的是手势和动作，不要求真的对上嘴型（Ray 2026-10-15）。抠绿幕后叠进画面。用在开头钩子、章节开头一句、结尾一句，每集约 30 秒。要逐字对口型时改 `"model": "pro"`（Kling AI Avatar，用这句配音驱动，贵一些）。

  没接入、留作备选的图生视频模型（2026-10-15 调研）：
  - LTX-2 Fast，约 $0.04/秒；
  - 本机 Wan2.2-TI2V-5B（mlx-video，24GB M4 Pro 上没实测）。

  本机跑不了：LTX-2.3（要 ≥32GB）、Wan 14B、H3 开源版（要 ≥42.5GB）。
- **角落**：其余时间缩在左下角只露头肩，用同一形象的换嘴型图层：每个字按拼音韵母选口型（A O E I U，b/p/m 先抿嘴），按逐字时间切换，加眨眼和轻微摆动。不花钱。
- 两者构图逐像素一致，大机位和角落之间缩放过渡，缩到角落后换成图层。段首提前 0.6 秒开始放大，段尾停 0.15 秒再用 0.8 秒缩回角落，都是 power2.inOut。主持人默认在开头从角落下方滑入；如果第一段大机位在 1.0 秒前开始，就改成第 0 帧直接在大机位、0.05 秒起 0.35 秒淡入，不先滑入再立刻放大（2026-10-13 Ray 反馈：开场 3 秒里的出现和缩放太突兀）。HyperFrames 模式（`assets/hf-template/host_build.py`）和手绘 kit 模式（`assets/template/overlay.js`）行为一致。
- 字幕压在主持人胸前，位置上移到 y≈1470。
- 形象是 Ray 的扁平卡通形象，去掉胡子胡青、面部干净；重做形象（`make_avatar.py`）时照此写提示词。

## 成本

| 部分 | 费用 |
|---|---|
| 形象（一次性） | `make_avatar.py`：candidates 3 张图 + build 7 张图，nano-banana-pro/edit |
| 大机位 | **h3（默认）**：约 $0.08/秒（官方国内单价没公开，按 fal 768P 价估），按生成时长计费，每截向上取整、最少 4 秒；走 `MINIMAX_API_KEY`。Kling pro $0.115/秒（1080p，对口型）；standard $0.056/秒（720p，测试时出现过手边多出一个红色贴纸，用的话必须抽帧检查） |
| 角落 | 0 |

每集大机位 30 秒左右：h3 约 $2.5，pro 约 $3.5。改了别的句子不会重新生成：h3 按「形象 + 这段的字和动作 + 时长」缓存，Kling 按音频内容缓存。Kling 按生成视频的实际时长计费，实测比音频段长约 10%，`--dry-run` 的估价已经乘了 1.1。

## 流程

1. **形象**（每个人只做一次，已有就跳过；Ray 的形象已在 `~/.config/ray-explainer/avatars/ray/`）。照片是个人生物特征数据，上传前必须在对话里得到本人同意：
   ```bash
   python3 $SK/scripts/make_avatar.py candidates <照片> --name <名字>   # 3 版扁平卡通，给用户挑
   python3 $SK/scripts/make_avatar.py build --name <名字> --pick <0|1|2> # 口型 / 眨眼图层，看 work/layers.jpg 检查接缝
   ```
2. **标大机位**：配音和 Whisper 校对（第 2、3 步）通过以后，在 `script.json` 顶层写：
   ```json
   "host": { "avatar": "ray",
             "big": [ {"scene": "hook", "line": 0, "act": "右手食指竖起，然后摊开双手"}, {"scene": "hook", "line": 2},
                      {"scene": "takeaway", "line": 2, "act": "双手在胸前比一个框，点头"} ] }
   ```
   `model` 不写就是 h3。`act` 是这一段的动作（h3 用），不写就用通用讲解手势（双手抬到胸前、摊开手掌、点头）。动作跟着句意写：提问摊手、强调竖食指、列举数手指、结尾点头；一段一个主动作，别堆三四个。H3 看不到画面上的其他东西，别写“指向左边的图表”这类要对位置的动作。
   `line` 从 0 数，和 cue 的 `line` 一致；同一幕相邻的句子会合成一段。选句子的原则：直接对观众说话、有情绪的句子（钩子、定义、金句、结尾提问）；画面要展示图表细节的句子留给角落。
   **先看这一句的主画面在哪**：大机位占住 x 272–808、y 1010 往下。主画面在正中偏下（比如结尾那个“塞不进安装包”的盒子）的句子，要么不选，要么给这一项加 `"pos": {"x": 660, "y": 1150, "w": 420}` 缩到右下角，手势照样看得见。
3. **先估价，再生成**：
   ```bash
   python3 $SK/scripts/host.py <project> --dry-run   # 段落 + 预计费用，贴给用户，等同意
   python3 $SK/scripts/host.py <project>             # 生成、抠图拆帧、写 host/plan.json
   ```
   之后照常 `render.js sheet / video`。改稿重新配音后，跑 `host.py` 重算口型；大机位句子没改的话命中缓存，不花钱。
4. **检查**：静帧检查时另外看大机位的几帧——手有没有伸出画面被裁、有没有多出来的物件（贴纸、文字）、白描边是否完整、形象大小有没有突然变（H3 偶尔会轻微推镜头）。有问题就删掉 `host/h3/<key>*`（Kling 是 `host/kling/<key>.mp4`）和 `host/frames/<key>/`，改 `act` 或直接重跑那一段。

   H3 的细节：首帧是 flat.png 左右各补 17% 绿边（3:4），手摊开不会碰边；帧保留这圈边，`plan.json` 段落带 `pad`，`overlay.js` 和 `host_build.py` 按它往外画，形象和角落图层照样逐像素对齐。超过 15 秒的段落分几截接力生成，下一截的首帧取上一截用到的最后一帧。H3 自带的音轨直接丢掉。接口是国内 `api.minimax.cn` 的 `/v2/video_generation`（`content` 数组格式，和 v1 的海螺接口不同），5 秒片约 2.5 分钟出。

## 横屏：只在关键句出现的小圆窗

`script.json` 写 `"aspect": "landscape"` 时（Ray 2026-10-14 定，参考小Lin说）：

- **样式**：左下角直径 164 的小圆窗（x 56、y 860），底色是画面的卡片色（`ray-ip` 白、`ray-ip-dark` 深灰 #2A2C2C），一圈 2 像素墨绿细圈（深色版提亮成 #0B6B69），不加投影；形象裁成头肩，照样换嘴型、眨眼。
- **只在关键句出现**：`host` 里写 `"show": [{"scene": "hook", "line": 0}, …]`，写法和 `big` 一样、不花钱；大机位句子自动算在内。开口前 0.3 秒弹出，说完停 0.15 秒再 0.3 秒淡出；同一幕相邻、或间隔不到 1.2 秒的句子合成一段。其余时间画面上没有主持人。`show` 和 `big` 都空 → 全片不出现（`host.py` 会提醒）。选句和大机位同一个原则：直接对观众说话、有情绪的句子（钩子、定义、金句、结尾提问），一集 3–6 句。
- **大机位**：同一个圆放大到直径 420（x 56、y 604），露出头肩和部分手势。`big[].pos` 横屏写 `{"x", "y", "w", "h"}`。
- **换边**（学小Lin说）：主画面在哪边，小圆窗就去另一边。那一幕写 `"host_side": "right"`，从这一幕开头起换到右下；之后写 `"left"` 换回来；不写沿用上一幕；第一幕写 `"right"` 就从右下开场。
- 版位都在 `assets/canvas.json` 的 `landscape.host`。改了 `show` / `host_side` / `theme` 要重跑 `host.py --plan-only`（HyperFrames 再跑 `host_build.py`）。kit / 语法模式（`overlay.js`）和 HyperFrames 模式（`host_build.py`）行为一致。
- 有主持人时内容区只到 y 850（`safe_host_bottom` 230），小圆窗和字幕在底部那一条，任何语法都不会被它盖住；大机位那几句例外，主画面避开它那一侧。

## 画面安排

- （以下是竖屏）有主持人时，主要画面放在 y 300–1440：字幕在 1470 附近，角落主持人从 1560 往下。语法片段会自动把下边的安全区放大到 480。
- 大机位句子期间，主持人占据 x 272–808、y 1010 往下。这几句的画面只放上半部（大字、标题、简单图形），不要放需要看清的图表细节。
- 封面（`RX_CLEAN=1`）不画主持人。
