# Ray 科普讲解稿

目标：写出一份观众看完**懂了一件事、带走一个东西、愿意转给朋友**的解说视频旁白。主角是这件事本身，不是 Ray 的观点。

它和 `ray-kb` 的分工：`ray-kb` 写 Ray 开机录的观点口播，判断说满、情绪说满；这里写讲解片的旁白，讲清楚、讲准确、讲得有意思。同一个素材两种都能做，看 Ray 要哪种；他说“科普”“讲解”“讲清楚原理”，或者明确说“不要太多我的判断”，就用这里。

## 动笔前

1. **完整读 [讲解表达规则](references/style.md)**，按里面的样本清单把样本整篇读完。规则不多，主要靠样本找语感。
2. 写一句 `central_judgment`：观众看完能复述的那一件事（“相机没拍到闪光，是因为快门打开的时间只占 5%”），不是 Ray 的立场。
3. **知识库预检（必做，联网调研之前）。** 跑 `python3 <vault>/50-系统/40-自动化/知识采集/knowledge_search.py <选题对象> <核心判断里的词> <可能的机制或类比>`，人名、产品名加引号。事件往往是新的，解释它的机制、类比、旧案例常常早就记过，第三类词最容易命中。它分三组输出：长期知识、过往调研（带日期，看清截至哪天，只补之后的变化）、已发布内容（上次怎么讲的）。输出整段贴进母稿「素材与来源」的「知识库预检」小节，没有相关结果也照贴（写「无相关」）；用上的知识在正文素材里注明，标「没有外部出处」的引用前回原始资料核对。知识库里没有这个脚本时，用 `rg -l` 在 `<vault>/20-知识` 正文里搜同样三类词，手写同样格式的小节。
4. **核实事实。** 讲解片里事实就是内容：每个数字、时间、人名、原话都要有一手或可靠来源。查不实的说法降到查得实的程度再写，不靠“待确认”兜底；只有措辞、取舍、口径差异进「待确认」。
5. 找素材：预检命中的知识、调研、原始录音和影像优先；需要时联网补数据。真实画面和原声能用就标出来（`【原声：……】`），解说视频以真实素材优先。

## 写成什么

一份母稿：`<vault>/10-创作/25-口播草稿/<日期>-<标题>.md`，套知识库的 `50-系统/30-模板/快速口播母稿.md`，frontmatter 改成：

```yaml
kind: oral-script
production_route: fast-oral
script_shape: explainer
video_format: 解说视频
central_judgment: "观众看完能复述的那一件事"
target_duration_seconds: 180
```

`production_route` 沿用 `fast-oral`，因为检查脚本和知识库的发布归档都按它识别母稿；`script_shape: explainer` 标明这是讲解稿，区别于 `ray-kb` 的 `opinion` 和 `narrative`。这两行不要加行尾注释，脚本按整行取值。

正文四段和快速口播一样：`口播正文`、`待确认`、`素材与来源`、`录制与发布收尾`。同一个题已有观点版母稿时，新建一份 `-科普版`，frontmatter 写 `supersedes: "[[旧母稿]]"`，旧稿不删。

发布之后按 `ray-kb` 的[发布回流](../ray-kb/references/fast-oral.md)做。讲解片最常留下的是第 1 类（原理、类比）和第 2 类（数字、事件），这两类别空着：

**发布回流三问（归档当次做，不留 `pending`）。** 正式稿末尾的「回流」小节（模板里有），每行写链接或「无」：

1. **机制与类比 → 长期知识**：这期有没有能迁移到别的题上的机制、类比、反直觉结论？先用 `knowledge_search.py` 查库里有没有，有就补进旧笔记，没有再新建概念或观点笔记，正文链回本篇正式稿和调研。
2. **带日期的事实 → 对象档案时间线**：这期查实的关键数字和事件，按事实发生的日期记进人物、公司、产品档案：`python3 <vault>/50-系统/40-自动化/知识采集/entity_timeline.py --from facts.json --write`（先不加 `--write` 预览；新对象在那条里加 `"create": "公司"`）。没有日期的不记。知识库里没有这个脚本时，在档案里手写 `## 时间线`，每行 `- YYYY-MM-DD 事实（来源：链接）`。
3. **讲法与反馈 → 留在本篇**：哪个开头、类比、画面有效，平台审核或数据上踩了什么坑。

三行都答完，`knowledge_backfill_status` 才写 `complete`（三行都是「无」时写 `not-needed`）。下次同主题开工，知识库预检会把这三样一起找出来。

`口播正文` 只放旁白和单独成行的 `【原声：……】`；不放镜头说明、列表、括号。字数 750–1000 字（复刻音色 1.1 倍速约 2.5–3.5 分钟）。数字的读法、句长等配音细节交给 `ray-explainer` 的 [解说稿规则](../ray-explainer/references/script-rules.md)，写稿时就照着写能省一轮返工。

**长视频**（Ray 2026-10-23 定，开始尝试）：目标是把一个故事完整讲完，时长跟着故事走，不硬压到三分钟，常见 6–10 分钟（约 2000–3300 字），`target_duration_seconds` 按估算写。长稿分成几章，每章开头用一个观众会问的问题接上一章；每一两分钟要有一个新的事实、反转或当事人原话，免得听疲。其余规则不变。Ray 说「长视频」「完整讲一个故事」，或者选题是人物故事、一件事的来龙去脉时，先按长视频写，交付时报估算时长。

## 检查与交接

```bash
python3 ../ray-kb/scripts/oral_script_check.py <母稿.md>
```

脚本只查结构（章节、列表和括号、🔴 条数、原声行格式），不查风格。交付前把正文从头默念一遍，再按 [讲解表达规则](references/style.md) 末尾的「交付前自查」过一遍。

交付时说清楚：文件路径、观众带走的那一件事、估算时长、「待确认」几条。要做成视频时，把母稿路径交给 `ray-explainer`（`script.json` 写 `"draft"` 指回母稿，配音直接用母稿正文）。

不自动发布，不生成付费图片或视频。
