# 原生快速口播

内容从灵感、现场观察、咨询案例或对话里的判断直接开始，没有现成长文时，用本模式。目标是缩短“想到”和“开机录制”之间的距离。

## 完成形态

整个生产阶段只保留一份文件：`<vault>/10-创作/25-口播草稿/<标题>.md`。它就是母稿，也是录制稿。

不要额外创建候选选题卡、写作任务、`content-pack` 或第二份口播包。用户本来就有相关笔记或调研，链接复用即可。

## 动笔前

1. 用一句话写出 `central_judgment`：这条视频只讲什么。
2. 想清楚观众是谁、处境如何：这个判断和建议，放在中国大陆普通打工人的现实里成不成立、做不做得到。不成立就换判断或换动作，不要靠加免责声明补救。
3. 按 [口播表达规则](voice.md) 读完样本。
4. 需要素材时，可以检索本地知识库、联网找新闻和数据。这些材料只是弹药，不是许可：找不到证据的观点照样说，拿不准的地方进「待确认」。

一条视频讲不清、需要好几个章节才能展开的内容，建议用户改走长文。

## 唯一母稿

使用知识库里的 `50-系统/30-模板/快速口播母稿.md`。frontmatter：

```yaml
kind: oral-script
status: draft
production_route: fast-oral
central_judgment: "观众看完只记住的一句话"
target_duration_seconds: 180
recording_status: pending
```

正文四段：

1. `口播正文`：只放能直接念的话，不混入镜头说明、列表或来源。
2. `待确认`：格式见 [口播表达规则](voice.md)。没有就写“无”。
3. `素材与来源`：用到的链接、本地笔记、截图或录屏想法。可以很短。
4. `录制与发布收尾`：状态、录后对照、发布确认、反馈和知识回写。

## 检查与录后学习

```bash
python3 scripts/oral_script_check.py <快速口播母稿.md>
```

脚本只查结构，不查风格。用户要求时再按 [口播稿四关审读](script-review.md) 审一遍。

用户给出实际录制稿时，按 [录后对照与表达学习](recording-feedback.md) 处理：保留生成稿版本，实际录制文本作为最终表达；录完只标记 `recorded`，不能推断已经发布。

## 发布回流

确认公开发布后，把最终逐字稿移到 `40-发布/50-口播视频/`，并完成：

- 确认实际发布平台；公开链接和准确发布时间可以留空；
- 建立正式反馈记录；
- 可复用的观点回写长期知识，或明确 `not-needed`；
- 有生成稿与录制稿差异时，留下对照入口。

`recorded`、已生成平台草稿和公开发布是三个不同状态，不互相推断。
