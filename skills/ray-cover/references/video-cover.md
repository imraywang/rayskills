# 视频封面：真人 + 大标题

视频封面和文章封面是两种东西。文章封面靠一个视觉隐喻，视频封面靠「人脸 + 大字」在信息流里抓人。这里只有通用的做法；用谁的照片、默认哪种风格和尺寸、品牌色，都在 [作者档案](../author-profile.md) 里。

## 流程

一期一张，按顺序走：

1. **读稿**：读这期的口播母稿或视频项目的 `script.json`，看 `central_judgment`、开头钩子和逐字稿，找出最抓人的那句。
2. **写文案**：见下文「文案」。直接用最合适的一组，另备 1–2 组交付时一起给。
3. **选风格**：用档案里写的默认风格；档案没写时按内容定一种构图（见「风格」），同一个系列保持不变。
4. **选照片**：只用档案里写明可以用的照片。没有档案、或用户这次没给照片并同意，就不做带真人的封面，改成文章封面的做法或先问。
5. **写提示词**：每个尺寸一份，结构见「提示词结构」。
6. **生成**：跑 `gen_cover.py`，见「生成」。
7. **验收和交付**：见「验收与交付」。

不发布、不上传平台。

## 人物

- 照片会随生图请求发给生图服务，属于个人生物特征数据。**用之前要有本人明确的同意**，同意的范围写在作者档案里；用别人的照片先问。
- 提示词写清：保留长相、发型、脸型和身份，一眼认得出是同一个人；姿势、手势、视线、表情按本期主题改；完整抠出作为独立主体，保持真实摄影质感，不卡通化、不磨皮。
- 服装写「保持参考图里的穿着」，不要写死某件衣服。参考图里有麦克风、领夹麦这类不该出现在封面上的东西，提示词里明确要求去掉。
- 模型会按主题自己加道具，道具可以留，但标题区里不能多出文字。道具涉及钱时写死币种和样式，否则模型会画成带人像的美元。
- 相邻几期不要连着用同一张照片。

## 文案

- **长度**：主标题最多两行，每行不超过 8 个字，字号极大。整句文章标题放不下就压缩，不要缩字号硬塞。
- **悬念**：留一个没说完的因果或反差，让人想点进来看答案：问句、反常结果、只给结论不给原因。不在封面上把答案说完。
- **小字和副标题**：默认不加，只有用户要求、或这期属于要靠栏目标签认出的系列时才加一行。提示词里写明「除主标题外不出现任何小字、标签或说明文字」，否则模型会自己加。
- 有几段字、各自多大、哪里用品牌色，跟着所选风格走。写法的其他规则（不编事实、不重复）见 [cover-copy.md](cover-copy.md)；那里的三层结构是给文章封面用的，视频封面不照搬。

## 风格

风格由作者自己定，写进档案：底色、人物怎么放、标题字形、品牌色用在哪、适合哪类内容。一个系列定下一个风格后保持不变，观众靠它认出栏目。

档案里没有定义风格时，按内容选一种构图起步：

| 内容 | 构图 |
|---|---|
| 观点、判断 | 人物半身，超大标题压在人物上方或被人物挡住一小部分 |
| 工具实测、工作流 | 人物居中，手边或身后放本期工具的抽象物件（不画真实品牌 logo） |
| 教程、常见问题 | 顶部一个问题，人物近景，胸前两行极粗的答案 |
| 概念解释 | 背后一行大字写问题，人物头肩，前面一张写关键词的大卡片 |
| 前后对比 | 上下两格，过程和结果各一个窄长大字 |

封面的任务是让人点进来，不是图好看。手上有平台后台的点击率数据时，按数据选风格，并把结论记进档案。

图表和刻度容易被模型标错位置：能不写数字就写「只有刻度线、不写数字」；真要写数字，验收时逐个核对。

## 比例与安全区

| 尺寸 | 用途 | 安全区 |
|---|---|---|
| `xhs` 3:4，1080 × 1440 | 小红书、视频号信息流；抖音、视频号也能用 | 四周至少 6%；在约 270 × 360 的缩略图里标题和人脸一眼看清 |
| `vertical` 9:16，1080 × 1920 | 抖音、视频号竖封面 | 标题、小字、人脸全部放在中间 3:4 的区域内：平台个人主页会把封面裁成 3:4；顶部 10% 和底部 20% 只放背景 |
| `channels` 6:7，1080 × 1260 | 视频号横屏视频的主页封面 | 同 xhs。生成接口没有 6:7：提示词写 1:1 正方形构图、上下留纯背景 |
| `card` 4:3，1440 × 1080 | 视频号分享卡片 | 人左字右，文字离右边缘至少 10%。生成接口没有 4:3：提示词写 3:2、顶部留纯背景 |
| `landscape` 16:9，1920 × 1080 | 横屏视频：YouTube、视频号 / 抖音横屏 | 人和标题左右分开；四周至少 5%；右下角约 18% × 14% 不放字（时长角标压在那里） |

默认出哪个尺寸看作者档案；没写时竖屏片出 `xhs`，横屏片出 `landscape`。

安全区是写提示词时的目标，验收时看的是**中心视觉完整**：标题、人脸、主道具在中间区域里完整可读即可。

每个比例分别写提示词、分别生成，不互相裁切。横屏片先定 16:9，认可后要出 3:4 时，把定稿的 16:9 当参考图，提示词写「把它重新构图成 3:4，保持同一个人、同样的姿势表情、同样的道具和字体处理，只改版式」。

## 提示词结构

按这个顺序写：

1. **角色和人物**：视频封面艺术总监和中文字体设计师；参考图是谁，保留长相和身份，姿势、表情按主题改，完整抠出，保持真实摄影质感。
2. **本期视频**：两三句讲清主题和核心观点，供模型找画面隐喻；不贴原文。
3. **画面文字**：逐字列出每段字、断行和层级，写明「只出现这几段文字，各出现一次，不加任何其他文字、英文、标语或水印」。不要在别处用引号写可能被画上去的话。
4. **颜色硬约束**：照作者档案的品牌色和禁用项写；肤色保持自然。深底上的暗色记号色容易被模型提亮成发光色，要写成「哑光、暗沉、不发光」。
5. **禁止项**：卡通化、多余的人、可读的网页或代码、品牌 logo、电商感、贴纸堆砌、文字压脸，加上档案里的禁用项。
6. **风格段**：按选定风格写底色、本期的视觉隐喻、人物姿势表情、标题字形和品牌色用在哪。
7. **画幅和安全区**：尺寸、像素、从上到下的构图，以及安全区硬约束。
8. **只生成一张**：不要多方案、不要拼图、不要手机界面框。

## 生成

```bash
python3 $SK/scripts/gen_cover.py <封面目录> --platforms xhs --ref <照片路径>
```

- 封面目录一期一个，可以几期并行跑。
- 两个生图后端的区别见 SKILL.md。比例对就缩放成目标像素并出 420px 缩略图，比例不对报错，不裁不拉。
- 只改局部用 `--edit`，写 `prompts/<p>-edit.md`，见 SKILL.md「修改」。
- **换人物、保留构图**：`--edit --ref <新照片>`，把定稿封面和新照片一起送进编辑接口。`prompts/<p>-edit.md` 写「第一张图是定稿封面，第二张图是同一个人的另一张照片。只做一处修改：把人物换成第二张图的样子，其余一切保持完全不变」。
- **补边**（`channels`、`card`）：生成接口只出固定比例。`gen_cover.py` 按纯背景的那条边取颜色和细纹补到目标比例，主体出边的那一侧不补；两边都不是纯背景就报错重跑。不裁、不拉伸、不镜像。

## 验收与交付

- 用 Read 逐张看：字逐字对（缺字、错字、多出来的字）；颜色符合档案；标题、人脸、主道具在安全区里完整可读（9:16 看中间 3:4）。
- **只改字时不重新生成**：用户认可了构图、只要删掉或改短一行字时，重新生成会换掉构图和脸。删一行字用 `scripts/erase_text.py`，它把框内的字抠掉再修补背景；纹理密的底或压在脸上的字不适用，那就重跑：

  ```bash
  uv run --no-project --with opencv-python-headless --with numpy python $SK/scripts/erase_text.py <旧版.png> <新版.png> x0 y0 x1 y1
  ```

  深色字加 `--dark`，出图后用 Read 和原图对照看。提示词同步改掉那行字，下次重跑时就不会再出现。
- 重跑前先把旧文件改名留档，加 `-v1`、`-v2` 后缀：`raw-<p>`、`<p>-cover`、`<p>-thumb`、生成日志、`manifest.json`、`ref.jpg`，提示词另存一份。`--edit` 时脚本会自动留档。
- 给 `ray-explainer` 成片做的封面，把成品拷进视频项目根目录，命名 `cover_3x4.png` / `cover_9x16.png` / `cover_16x9.png`，发布脚本会自动写进发布包。
- 用 SendUserFile 发成品，回复里写：用的风格、照片和一句话视觉隐喻；这组文案和 1–2 组备选；验收发现的问题和处理。
