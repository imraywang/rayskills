# 交稿前检查

只查三件事。不要为了通过检查把文章改得更稳、更克制。

## 1. 像不像 Ray

- 读起来是 Ray 本人在说话，观点和情绪是说满的。
- 正文里没有任何自保的话：“我没办法保证”“这不是说……”“当然……但……”“需要说明的是”“仅代表个人观点”。
- 有“我”：有作者的经历、情绪和判断，而不是一篇资料综述。
- 拿不准、编补的内容都进了文末「待确认」，没有留在正文里对冲。
- 放在中国大陆观众的真实处境里成立：给的建议是他们真做得出来的，读者会觉得“他懂我”，而不是“说得轻巧”。

标准见 [voice.md](voice.md)。拿不准时，把稿子和样本放在一起读一遍。

## 2. 能不能发

- 面向公众号或 X 的长文有二级标题作为阅读锚点，标题推进判断，不写“背景”“分析”“总结”这类目录词。
- 加粗帮读者在手机上扫到关键问题、冲突和判断。
- Markdown 段落之间只留一个空行，没有连续空行造成的空白段落。
- 文末有 `## 待确认`，没有要确认的写“无”；frontmatter 有 `publish_exclude_sections: 待确认`，推送时这一节会被剔除。

## 3. 读不读得顺

最终交付前从头朗读一遍，读不顺的地方直接改。

`article_check.py` 只查格式和篇幅，不查风格。错误必须修改；提醒逐项判断，可以保留。
