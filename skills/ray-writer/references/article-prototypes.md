# 长文原型

原型是完稿后的结构诊断工具，不是动笔前必须套用的提纲。正文已经能围绕一个问题自然推进时，不必读取本文件；文章跑散、教程不可执行或案例边界不清时，再识别一个主原型检查缺口。

下列推进方式是常见有效路径，不是必须逐项出现的章节顺序。

## 现象解读

适合从公开观点、行业变化或平台动作推出更大的判断。

常见推进：具体变化 → 常见解释 → 信号为何失效 → 核心迁移 → 必要的反方或边界 → 对平台或个人的影响 → 余波。

重点是让读者重新理解一件已经看见的事。通常使用连续短段落，不必设置小标题。

## 观点论证

适合作者已经有明确主张，需要证明它为何成立。

常见推进：争议命题 → 证据和机制 → 边界 → 反例 → 修正后的更强判断。

不要只找支持材料。最强反方必须让原判断发生收缩、补充或升级。

## 个人实践

适合真实工具体验、工作流搭建、项目复盘和做事过程。

常见推进：真实目标或痛点 → 最初做法 → 失败或返工 → 关键改变 → 可验证结果 → 得出的判断 → 他人如何最小化复用。

事实价值高于戏剧性。不能补造失败、对话、耗时和效果。为了可读性可以调整叙述顺序，但不能改变事实因果。

## 案例拆解

适合公司、产品、人物或一线实践案例。

常见推进：结果或反常识 → 背景 → 关键选择 → 运行机制 → 为什么有效 → 失效边界 → 可迁移判断。

不要把单个案例写成普遍规律。优先保留关键选择发生前的真实阻力，以及后来让判断得到验证的前后变化；读者先看见证据，再接受抽象结论。成功案例还要说明同一种做法会因哪些具体条件失败，不能只贴“幸存者偏差”标签。

## 教程与方法

适合读者需要照着完成任务。

常见推进：适用对象和结果 → 前置条件 → 判断原则 → 分步操作 → 常见失败 → 验收方式 → 下一步。

教程必须使用清楚的小标题、步骤和必要清单。不要把现象解读型“不设标题”的规则套进来。先讲为什么这样判断，再给操作。

## 案例承载方法

案例和方法同时不可删除时，以案例证明判断，以方法完成迁移。先让人物、选择、阻力和结果组成证据链，再提炼读者可以执行的步骤；不要在每个事实后立刻插入一段大道理，也不要从一个成功案例直接跳到普遍公式。

## 诊断规则

- 材料的价值主要来自公开信号及其含义：现象解读。
- 价值主要来自明确立场和争议：观点论证。
- 价值主要来自用户亲自做过：个人实践。
- 价值主要来自一个外部对象的运行方式：案例拆解。
- 价值主要来自读者要完成一件事：教程与方法。

如果两种都像，问文章删去哪一部分就不成立。不可删除的那部分对应主原型。识别后只修复缺口，不要把整篇文章重排成原型清单。
