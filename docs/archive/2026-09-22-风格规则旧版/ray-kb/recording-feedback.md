# 录后对照与表达学习

这份规则负责把“生成的口播稿”与“Ray 实际录制的最终文本”之间的变化，转成下一次写稿可以使用的经验。它不替代事实核对、四关审读或结构检查。

## 两个真源不要混

- 母稿与事实清单是事实、数字和判断边界的真源。
- Ray 提供的实际录制文本是字幕、发布归档和后续衍生表达的真源。

实际录制稿出现新的数字或更强的事实表达时，原样保留录制文本，同时把差异记入核对项。未经确认，不把它扩写成封面、醒目字幕或图文结论。

用户只说“这是最终录制稿”，代表录制完成，不代表已经公开发布。没有平台、公开链接和发布时间时，状态只能到 `recorded`。

## 什么时候进入这条流程

出现以下任一请求时进入录后对照，而不是重新审稿：

- “这是我最后录的口播稿。”
- “对比一下我录的和你写的 difference。”
- “把这次修改沉淀下来，以后写得更像我。”

如果用户只给最终稿、找不到生成稿，仍然可以归档最终稿，但不能虚构差异；明确说明本次缺少成对样本。

## 对照步骤

### 1. 冻结两版

记录生成稿路径、版本或内容指纹，以及最终录制稿路径和内容指纹。不要用最终稿直接覆盖唯一的生成稿而不留下比较入口。

最终录制正文必须原样保留。对照报告可以引用代表句，但不另造一份“更好的最终稿”。

### 2. 先找叙事发动机

分别用一行箭头写出两版推进顺序。先回答：

- 这版在证明什么，还是在带观众经历什么？
- 谁是主角：数据、案例、框架，还是一个人的变化？
- 观众在前 30 秒是否知道后面为什么值得听？

如果叙事发动机不同，先解释这个差异，再看句子。不要把结构变化降格成“更口语”。

### 3. 比较四个层面

1. **材料取舍**：哪些数据、案例和产品名被删掉、泛化或前移？它们原来服务什么？
2. **现实变化**：抽象概念是否被改成“一个人现在能做什么、得到什么、承担什么”？
3. **口语桥**：哪些“那、但你注意、说白了、我必须说一句实话”被加入？它们是否在开问题、转向或降温？
4. **行动设计**：结尾是否让观众能判断自己在哪、下一步做什么，而不只是记住一句话？

长度和朗读时长只作辅助。更短不一定更好，更长也不一定更完整。

### 4. 给规律分级

- **稳定规则**：至少两个独立的实际录制样本重复出现，可以进入所有相关口播的写前检查。
- **原型规则**：用户明确修改并在最终录制中采用，但只适用于某类叙事，如个人结果复盘、咨询案例或教程。
- **待观察**：只出现一次，或可能由本期题材造成。记录下来，但不自动约束下一篇。
- **撤回规则**：后续样本反复与旧规则相反。保留变更原因，不静默覆盖历史。

用户明确说“以后所有内容都这样”时可以直接升级；否则不要把一次临场改动写成永久人设。

## 当前稳定规则

以下规则已有至少两组实际录制删改记录支持：

1. **个人结果要放回具体处境。** 不只报数字，也交代当时的约束、失败、感受或为什么普通人能代入。
2. **数据服务转折，不展示全部研究过程。** 保留能改变理解的数字，删除重复证明和只体现工作量的数据。
3. **口语桥按功能判断。** 能打开问题、完成转向、主动降温或建立信任的口语，不按口水话机械删除。
4. **结尾兑现本期承诺。** 方法型、求助型内容可以给自测、门槛或下一步；观点型内容可以停在作者愿意承担的判断，不强塞行动或评论邀请。2026-09 的已发布样本修正了旧版“每篇都给动作”的过度概括。
5. **技术过程默认退到幕后。** 除非题目本身是教程，产品名、采集过程和后台步骤不能抢走人的判断。
6. **从被看错的表象推进到真正的判断标准。** 先让观众看见一个常被讨论、却不足以决定结果的指标或表象，再用具体场景、例子或数据说明为什么不够，最后交代该看什么。标准必须随题目变化，不能把“不是 A 而是 B”当固定句式。

## 2026-09 已发布口播补充：判断型与个人经验型

本节依据已发布文稿更新写前风格，不声称已逐字核对平台成片。优先证据是 Ray 直接提供的已录文本 [[40-发布/50-口播视频/2026-09-21-Jev真有那么强么]]、本人撰写并确认发布的 [[40-发布/50-口播视频/2026-09-15-不要让标签变成你的上限]]，以及已有生成稿与实际录制稿对照的 [[30-资料/10-自主调研/2026-08-20-AI红利个人复盘/口播初稿与实际录制版对照]]。[[40-发布/50-口播视频/2026-09-13-AI什么都知道就是不知道公司怎么干活]]、[[40-发布/50-口播视频/2026-08-25-企业AI转型最危险的倒挂]]等已发布文稿只作交叉观察；未核实与成片逐字一致的地方，不推断为录制时的修改。

### 可复用的表达习惯

- **直接说自己在判断什么。** 可以说“我发现”“我觉得”“对我来说”，随后交代观察、计算、例子或亲身经历。不要把这些词统统删成无主语的权威口吻；也不要只靠第一人称代替证据。
- **让抽象争论落到一个可辨认的差错。** Jev 稿用“心算很快却算错”说明速度不能代替准确度；企业案例用“库存有 17 个，但这 17 个现在能不能用”说明数据不等于工作结果。类比只负责打开理解，后面仍要回到任务本身的判断标准。
- **先给观众一个可跟随的问题，再逐步换掉错误尺度。** Jev 从“强不强”追到概率能否信、四类工作流准确度、最后落在 Agent Harness 的分工；AI 红利从个人结果追到现实兑现；个人标签稿从确诊带来的解释力走到标签可能限制行动。保留原来的因果顺序，别为了压缩把中段跳成结论清单。
- **口语桥可以朴素，节奏不必均匀。** “然后我发现”“但问题是”“所以归根结底”在已发布稿里承担转向；个人经历可以反复强调一个词，判断型内容可以连用追问。按它是否推动下一步决定去留，不按“口头禅禁用表”机械清理。
- **批评对象要落在可检验的主张上。** Jev 稿对夸大宣传的语气很硬，真正可复用的是拆出“别的模型是否也会做”“概率是否可信”“能否用于生产”三项检验。可以保留锋芒，不把未经核实的效果、动机或全网范围扩写为事实。

### 按题材选择推进方式

- **模型与产品判断**：热议或表面优势 → 一个能暴露问题的类比/场景 → 同任务下的能力证据与适用边界 → 作者对工作流的判断。Jev 属于这一型；不复制心算题、90% 或收尾句。
- **个人经验反思**：真实经历 → 最初得到的帮助或收益 → 它后来造成的限制 → 自己怎样调整 → 可留给观众的提醒。标签稿属于这一型；不把未经本人提供的诊断、经历或改变效果迁移到别的稿。
- **企业现场问题**：具体人和事 → 看似合理的方案在哪里卡住 → 谁缺少信息、权限或收益 → 需要怎样改流程。现场案例和组织倒挂稿可作结构参考；没有一手材料时不能补写“我在现场”。

这些是叙事原型，不是每篇必须填满的段落模板。判断型可以只落在结论；经验型可以给提醒；教程和求助型才需要清晰的操作动作。

## “个人结果复盘”原型规则

这组规则来自《普通人如何抓住 AI 红利》的明确修改，只约束同类选题：

```text
个人结果与现实约束 → 核心问题 → 提前给地图 → 逐层讲现实变化 → 在关键层用数据降温 → 实践闭环 → 同框架自测 → 作者判断
```

使用时注意：

- 结果之后先兑现观众的问题，不急着进入反驳模式。
- 有自定义多层框架时，尽早告诉观众层数和价值，不把框架藏到后半段。
- 每层都回答“现实中发生了什么变化”，不只解释名词。
- 最重要的一层可以明显更长，不为结构整齐平均分配篇幅。
- 方法之后用同一框架让观众自测，避免框架只属于作者。

## 下一次生成前怎么用

1. 先判断本篇属于哪种叙事原型，再读取对应规则。
2. 用一句话写清叙事发动机；如果写不出来，先不要铺数据和案例。
3. 稳定规则全部检查，按题材选一种自然的推进方式；不要给观点型结尾硬加行动步骤。原型规则按需使用，待观察项不自动执行。
4. 不复制上一条视频的开场句、四层名称或结尾金句；学习的是推进方式，不是表面句式。

## 对照报告格式

1. 一句话写出最根本的 difference。
2. 分别画出两版叙事顺序。
3. 对比开场、框架位置、数据、案例、现实结果、行动和结尾。
4. 说明生成稿保留了什么价值，不能只写最终稿更好。
5. 输出稳定规则、原型规则和待观察项。
6. 写清这次具体回写了哪些 Skill 规则；用户未要求改稿时，不再生成第三版。
